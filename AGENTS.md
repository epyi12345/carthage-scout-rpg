# Project Rules

## Goal

Build a small, testable MVP before expanding the full game.

The MVP should prove the core fantasy:

> A lone scout must map a route that Hannibal's army can survive.

## Work Style

- Prefer small issues.
- Prefer small PRs.
- Keep GDD changes and prototype changes separate when possible.
- Every system must connect to at least one of:
  - survival
  - map quality
  - return risk
  - Hannibal's army result

## MVP Priority

1. Core loop
2. Map observation and recording
3. Return and marking system
4. Survival resources
5. Ending simulation

## Avoid

- Large combat systems before the map loop works.
- Too many companions in MVP.
- Overbuilding tribe politics before the first prototype.
- Randomness that feels like pure guessing.
